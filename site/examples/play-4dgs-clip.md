# Play a Faltwerk 4DGS

**What you get:** a moving capture (a 4D Gaussian splat clip in [Faltwerk](https://github.com/edrethardo/Faltwerk)'s
`.csgs` format) with play, pause, a scrub bar, speed and loop controls,
driven by the same `AnimationMixer` a glTF animation uses.

The clip is VLAM's own goose: the pixel-art mascot as 149,000 splats, walking
in place and honking in a two-second loop (3.2 MB, generated by
`scripts/generate-goose-clip.mjs`). Add `?clip=<url>` to the live page to play
another [Faltwerk](https://github.com/edrethardo/Faltwerk) `scene_*.json`.

## Load, then play like a glTF animation

`loadSplatClip` picks the format from the URL (a Faltwerk `scene_*.json`
here), fetches the clip and decodes it in a worker. `SplatClipMesh` plays
any clip it returns, whatever the format; its `animation` is an
`AnimationClip` with one track on the mesh's `time` (seconds), so an
`AnimationMixer` gives you pause, scrub, speed and loop modes for free:

```ts
const mixer = new THREE.AnimationMixer(mesh);
const action = mixer.clipAction(mesh.animation);
action.play();

action.paused = true; // pause
action.time = 1.2; // scrub
action.timeScale = -1; // backwards
```

Call `mesh.update(camera, renderer)` every frame after `mixer.update`: that is
where the mesh shows `time`'s frame and uploads upcoming sections.

## Which path it plays on

A format can bring its own GPU path: for `.csgs` on WebGPU the curves are
evaluated on the GPU and a frame costs no upload. Everywhere else (WebGL2, or
a format without one) the clip evaluates whole frames and the mesh swaps
them in.
`mesh.playback` says which one the constructor picked, which is why the
renderer must be initialized before the mesh is built. The
[dynamic splats guide](https://github.com/Voluma-ai/vlam/blob/main/docs/guide/dynamic-splats.md)
covers both paths, the unified draw with a scene, and the known limits.
